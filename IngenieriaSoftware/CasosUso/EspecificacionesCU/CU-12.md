### Caso de Uso 12 (CU-12)
* **Nombre:** Procesar Simulación en Diferido
* **Descripción:** al inicializar una partida tras un periodo de inactividad, el motor restaura el último estado consistente, calcula los ciclos vencidos a partir del tiempo transcurrido y procesa el desfase sin duplicar efectos.
* **Actores:** Motor de Simulación
* **Precondición:** existe una partida persistida con el último estado consistente, el instante del último ciclo y el remanente del temporizador; se dispone del tiempo transcurrido desde la última desconexión.
* **Postcondición:** el sistema restaura el estado confirmado y, si corresponde, procesa los ciclos vencidos en orden, aplicando las restricciones offline de alimentación y enfermedad. Los ciclos y el nuevo remanente quedan persistidos de forma idempotente.
* **Situaciones de Error:** no se puede restaurar el estado o calcular el desfase, el temporizador persistido es inconsistente, falla la ejecución de un ciclo o se interrumpe la recuperación.
* **Situación del Sistema en caso de Error:** no se presenta ni conserva un estado parcialmente aplicado. El sistema vuelve al último estado consistente confirmado y puede reintentar el procesamiento sin duplicar ciclos ni sus efectos.
* **Flujo Básico:**
  1. Al iniciar la aplicación, el motor recupera el último estado confirmado de la partida y lee el remanente del temporizador `R` y el tiempo transcurrido `E` desde la desconexión, en segundos.
  2. El sistema valida los datos temporales y calcula los ciclos vencidos y el nuevo remanente:
     * Si `E < R`, no vence ningún ciclo y el nuevo remanente es `R - E`.
     * Si `E >= R`, se procesan `1 + floor((E - R) / 600)` ciclos y el nuevo remanente es `600 - ((E - R) mod 600)`; un resto igual a cero se representa como `600`.
     * El número de ciclos procesados no supera `retencion.max_ciclos_offline`; los ciclos que excedan ese máximo se descartan y el remanente se calcula igualmente.
  3. Si vencieron ciclos, el motor los procesa en orden cronológico, asignando a cada uno una identidad única e impidiendo repetir un ciclo ya confirmado. En cada ciclo mantiene el orden definido para la simulación: edad, alimentación, salud, ciclos críticos, defunciones, reproducción, beneficios, misiones, métricas y persistencia.
  4. Durante la resolución offline, el sistema limita el descenso de alimentación a los tramos permitidos por RF-22: desde los estados previos `[100, 80, 60]%` hasta `40%`, o desde `[40, 20]%` hasta `0%`; si el animal ya estaba al `0%`, computa como máximo un único ciclo mortal.
  5. El sistema aplica la restricción offline de enfermedad de RF-23: un animal que enferma durante el diferido computa un ciclo en ese estado y uno que ya estaba enfermo acumula como máximo dos ciclos adicionales.
  6. El sistema conserva contadores de desnutrición y enfermedad independientes, reinicia el correspondiente cuando se recupera ese estado y utiliza el contador mayor si ambos estados críticos coinciden para decidir la defunción.
  7. Cada ciclo vencido confirma y persiste su estado esencial como una operación consistente antes de continuar con el siguiente. La satisfacción y las métricas intermedias se calculan en memoria; al terminar el último ciclo, el sistema escribe una sola vez las métricas finales, los avisos generados (sin duplicar el mismo aviso por ciclo) y un único registro de auditoría de la recuperación, ejecuta la purga de retención y persiste el nuevo remanente. Si no venció ningún ciclo, persiste únicamente el remanente actualizado.
  8. El motor deja la partida lista para su uso y permite que la aplicación muestre el estado recuperado.
* **Flujo alternativo:**
  * **1.a: no se puede recuperar el último estado consistente.** El sistema no ejecuta ciclos sobre datos incompletos y comunica que la partida no pudo restaurarse.
  * **2.a: `E < R`.** El sistema no ejecuta ciclos ni recálculos derivados de simulación; actualiza el remanente a `R - E` y continúa la inicialización.
  * **2.b: falta o es inconsistente el remanente o el tiempo transcurrido.** El sistema no supone valores temporales y no procesa ciclos hasta poder validar el desfase.
  * **2.c: los ciclos vencidos superan el máximo offline.** El sistema procesa solo el máximo configurado, descarta el resto y calcula el remanente con la fórmula habitual.
  * **3.a: uno de los ciclos calculados ya está confirmado.** El sistema reutiliza su resultado y solo procesa los ciclos pendientes que no estén confirmados.
  * **4.a: la alimentación ya alcanzó el límite offline permitido.** El sistema no aplica descensos adicionales fuera de los tramos autorizados; conserva la regla de un único ciclo mortal si el animal ya estaba al 0%.
  * **5.a: el animal enferma durante un ciclo diferido o ya estaba enfermo.** El sistema limita sus ciclos de enfermedad según RF-23 y no acumula ciclos adicionales no permitidos.
  * **6.a: el estado crítico recuperado o los contadores no pueden validarse.** El sistema revierte la recuperación en curso y conserva el último estado confirmado.
  * **7.a: ocurre un cierre inesperado o falla una escritura durante el procesamiento.** El sistema recupera el último estado consistente en la siguiente apertura y reintenta solo los ciclos no confirmados, completa la escritura final de métricas, avisos y auditoría y no duplica beneficios, avisos, progreso o métricas.

### Reglas y valores aplicables
Las transiciones biológicas son las de `EspecificacionBBDD.md` (sección 2.3.1) con los límites offline de RF-22 y RF-23; el sorteo de enfermedad de un animal se detiene al enfermar. El cálculo temporal se limita a lo especificado por RF-21 y RF-24.
