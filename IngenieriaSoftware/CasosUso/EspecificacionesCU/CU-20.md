### Caso de Uso 20 (CU-20)
* **Nombre:** Consultar Misiones y Progreso
* **Descripción:** el gestor consulta una misión vigente por cada tipo configurado, sus objetivos, el progreso registrado y las recompensas asociadas o disponibles para reclamar.
* **Actores:** Gestor del Zoo
* **Precondición:** existe una partida seleccionada y el sistema puede recuperar las misiones y el progreso persistido.
* **Postcondición:** el sistema presenta una sola instancia vigente por tipo, sin recalcular ni modificar el progreso durante la consulta. Las misiones cumplidas no reclamadas muestran la acción explícita de reclamar.
* **Situaciones de Error:** no se pueden recuperar las misiones, sus objetivos, el progreso o la recompensa configurada.
* **Situación del Sistema en caso de Error:** el sistema identifica la información que no pudo cargar y no inventa objetivos, progreso o recompensas. La consulta no modifica el estado de las misiones ni acredita recompensas.
* **Flujo Básico:**
  1. El gestor abre el apartado de misiones y progreso.
  2. El sistema consulta la instancia vigente de cada tipo configurado, su estado persistido, los objetivos actuales, el progreso y la recompensa asociada.
  3. El sistema presenta cada misión con su objetivo, progreso actual, condición de cumplimiento y recompensa, usando nombres descriptivos y sin mostrar claves internas.
  4. El sistema respeta la naturaleza del progreso configurado: las compras, ventas y niveles alcanzados son acumulativos; las condiciones de animales vivos por hábitat y de satisfacción reflejan su estado actual y pueden disminuir; la de prestigio no disminuye porque el prestigio nunca baja.
  4.1. El sistema ordena la lista: primero las misiones cumplidas pendientes de reclamar, en el orden en que se cumplieron; después el resto, de más a menos avance y, a igual avance, la que menos le falta. Cada misión muestra su avance con una barra.
  5. El sistema refleja el cumplimiento registrado inmediatamente después del evento relevante o del ciclo que lo produjo. Una misión cumplida y no reclamada muestra una acción explícita para reclamar su recompensa.
  6. Si el gestor acciona reclamar, el sistema deriva al flujo CU-15, que valida y acredita la recompensa; la lectura de la vista por sí sola no ejecuta esa mutación.
  7. Después de una reclamación confirmada, la vista muestra la nueva instancia progresada del tipo correspondiente. La consulta no crea instancias, no aplica progresión y no conserva un historial funcional de las anteriores.
* **Flujo alternativo:**
  * **1.a: no hay instancias configuradas disponibles.** El sistema informa de que no hay misiones que mostrar y no crea ni reactiva instancias durante la consulta.
  * **2.a: no se puede recuperar el objetivo o el progreso de una misión.** El sistema informa del dato no disponible y no estima el progreso a partir de la vista.
  * **2.b: no se ha configurado una recompensa o no se puede determinar su contenido.** El sistema indica que la información está pendiente o no disponible y no presenta un premio supuesto.
  * **3.a: un objetivo depende de una configuración pendiente.** El sistema presenta solo los datos configurados y no asigna cantidades, umbrales ni probabilidades nuevos.
  * **4.a: una condición dinámica ya no se cumple al consultar.** El sistema muestra el estado vigente persistido, que puede ser inferior al progreso mostrado anteriormente, según la regla de esa misión.
  * **5.a: la misión no está cumplida o ya fue reclamada.** El sistema no ofrece una acción de reclamación válida; la idempotencia se valida nuevamente en CU-15.
  * **6.a: el gestor no confirma o abandona la reclamación.** No se acredita la recompensa y la misión conserva el estado correspondiente.
  * **7.a: una reclamación ya fue confirmada.** El sistema presenta la instancia siguiente persistida; un reintento de la reclamación devuelve el resultado idempotente y no vuelve a acreditar la recompensa.

### Reglas y valores aplicables
Valores de objetivos, contadores y recompensas: `Misiones/EspecificacionMisiones.md`, secciones 4.1 y 8. Un tipo `AGOTADA` no se muestra como misión vigente. Orden de la lista y recompensa de la misión de prestigio: `Otros/DecisionesImplementacion.md`, secciones 5.1 y 5.2. La consulta no recalcula progreso ni provoca sondeos; las actualizaciones ocurren por eventos relevantes o al finalizar un ciclo.
