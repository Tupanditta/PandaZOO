### Caso de Uso 20 (CU-20)
* **Nombre:** Consultar Misiones y Progreso
* **Descripción:** el gestor consulta las misiones activas, sus objetivos, el progreso registrado y las recompensas asociadas o disponibles para reclamar.
* **Actores:** Gestor del Zoo
* **Precondición:** existe una partida seleccionada y el sistema puede recuperar las misiones y el progreso persistido.
* **Postcondición:** el sistema presenta las misiones y su estado vigente sin recalcular ni modificar el progreso durante la consulta. Las misiones cumplidas no reclamadas muestran la acción explícita de reclamar.
* **Situaciones de Error:** no se pueden recuperar las misiones, sus objetivos, el progreso o la recompensa configurada.
* **Situación del Sistema en caso de Error:** el sistema identifica la información que no pudo cargar y no inventa objetivos, progreso o recompensas. La consulta no modifica el estado de las misiones ni acredita recompensas.
* **Flujo Básico:**
  1. El gestor abre el apartado de misiones y progreso.
  2. El sistema consulta las misiones activas, su estado persistido, los objetivos configurados, el progreso y la recompensa asociada.
  3. El sistema presenta cada misión con su objetivo, progreso actual, condición de cumplimiento y recompensa, usando nombres descriptivos y sin mostrar claves internas.
  4. El sistema respeta la naturaleza del progreso configurado: las compras, ventas y edades alcanzadas son acumulativas; las condiciones de animales vivos por hábitat, satisfacción y prestigio reflejan su estado actual y pueden disminuir.
  5. El sistema refleja el cumplimiento registrado inmediatamente después del evento relevante o del ciclo que lo produjo. Una misión cumplida y no reclamada muestra una acción explícita para reclamar su recompensa.
  6. Si el gestor acciona reclamar, el sistema deriva al flujo CU-15, que valida y acredita la recompensa; la lectura de la vista por sí sola no ejecuta esa mutación.
  7. El sistema conserva el histórico de misiones reclamadas aunque estas dejen de aparecer entre las misiones activas.
* **Flujo alternativo:**
  * **1.a: no hay misiones activas.** El sistema muestra que no existen misiones activas y no crea ni reactiva misiones.
  * **2.a: no se puede recuperar el objetivo o el progreso de una misión.** El sistema informa del dato no disponible y no estima el progreso a partir de la vista.
  * **2.b: no se ha configurado una recompensa o no se puede determinar su contenido.** El sistema indica que la información está pendiente o no disponible y no presenta un premio supuesto.
  * **3.a: un objetivo depende de una configuración pendiente.** El sistema presenta solo los datos configurados y no asigna cantidades, umbrales ni probabilidades nuevos.
  * **4.a: una condición dinámica ya no se cumple al consultar.** El sistema muestra el estado vigente persistido, que puede ser inferior al progreso mostrado anteriormente, según la regla de esa misión.
  * **5.a: la misión no está cumplida o ya fue reclamada.** El sistema no ofrece una acción de reclamación válida; la idempotencia se valida nuevamente en CU-15.
  * **6.a: el gestor no confirma o abandona la reclamación.** No se acredita la recompensa y la misión conserva el estado correspondiente.
  * **7.a: se consulta una misión reclamada.** El sistema conserva su estado histórico, pero no la vuelve a mostrar como misión activa ni permite reclamarla otra vez.

### Puntos pendientes
Los valores concretos de objetivos, umbrales, contadores y recompensas, así como la representación final de algunos progresos acumulativos, se definen en la configuración del proyecto. La consulta no recalcula progreso ni provoca sondeos; las actualizaciones ocurren por eventos relevantes o al finalizar un ciclo.
