### Caso de Uso 7 (CU-07)
* **Nombre:** Adquirir Insumos
* **Descripción:** el gestor del Zoo compra alimento o insumos médicos en la tienda, paga el coste correspondiente con los fondos disponibles y aumenta el inventario del tipo de recurso adquirido.
* **Actores:** Gestor del Zoo
* **Precondición:** el gestor accede a la tienda de la partida y existe al menos un recurso elegible para adquirir.
* **Postcondición:** tras confirmar una compra válida, el saldo disminuye por el coste total, el inventario del recurso seleccionado aumenta por la cantidad adquirida y la transacción queda persistida y auditada. El saldo y el inventario no pueden quedar negativos.
* **Situaciones de Error:**
  * La compra no se completa porque no hay recursos elegibles, la cantidad o el coste no se pueden validar, el saldo es insuficiente o se produce un error durante la operación.
* **Situación del Sistema en caso de Error:**
  * Si la compra no se confirma, no se descuentan fondos, no se incrementa el inventario ni se registra una compra parcial; el sistema conserva el estado previo e informa el motivo.
  * Si se produce un error antes de confirmar la operación, el sistema revierte conjuntamente el cambio de saldo, el cambio de inventario y el registro económico/auditoría que corresponda.
* **Flujo Básico:**
  1. El gestor del Zoo accede a la tienda y elige adquirir alimento o insumos médicos.
  2. El sistema muestra bambú como único alimento cuando haya especies alojadas que lo demanden, además de los insumos médicos disponibles. Indica para cada recurso su unidad y precio unitario configurados, sin exponer identificadores internos.
  3. El gestor selecciona un recurso e indica la cantidad que desea adquirir en la unidad indicada: kilogramos de alimento o unidades de insumo médico.
  4. El sistema valida que el recurso pertenece al catálogo elegible y que la cantidad es positiva y válida para su unidad. Calcula el coste total usando el precio unitario configurado y la cantidad solicitada, y muestra recurso, cantidad, unidad, coste total y saldo disponible.
  5. El gestor confirma la compra.
  6. Antes de confirmar, el sistema vuelve a validar el recurso, la cantidad, el precio aplicable y que el saldo disponible cubra el coste total.
  7. Si las validaciones son correctas, el sistema registra atómicamente el cargo, el incremento del inventario y el movimiento económico, y persiste el resultado y la auditoría conforme a RF-46 y RF-47. Un reintento de la misma solicitud no debe duplicar el cargo ni la cantidad acreditada.
  8. El sistema muestra el nuevo saldo y el stock actualizado. La compra de recursos no provoca por sí sola recálculos de satisfacción ni de simulación; la navegación y consulta de la tienda tampoco generan mutaciones.
* **Flujo alternativo:**
  * **1.a: no hay recursos elegibles para adquirir.** El sistema no inicia una compra ni modifica fondos o inventario. Si no hay especies alojadas que demanden alimentos, no ofrece bambú ni alimentos fuera del catálogo permitido.
  * **3.a: el gestor cancela antes de confirmar.** El sistema abandona el flujo sin descontar fondos, incrementar el inventario ni registrar una compra.
  * **3.b: la cantidad está vacía, no es positiva o no es válida para la unidad del recurso.** El sistema rechaza la solicitud, indica el error y no modifica el estado.
  * **4.a: el recurso deja de pertenecer al catálogo elegible o ya no está disponible antes de confirmar.** El sistema rechaza la compra y conserva saldo e inventario.
  * **4.b: no se dispone de un precio unitario configurado o no es posible calcular el coste total.** El sistema no permite confirmar ni utiliza un precio supuesto.
  * **6.a: el saldo disponible es inferior al coste total.** El sistema bloquea la compra sin realizar cargos ni modificar el inventario.
  * **6.b: el coste, el saldo o la elegibilidad del recurso cambian antes de confirmar.** El sistema vuelve a validar la operación; si no se cumplen las condiciones, la rechaza sin cambios parciales y muestra el motivo.
  * **7.a: falla la persistencia o se produce un error durante la confirmación.** El sistema revierte la transacción completa, conserva los fondos y el inventario previos y notifica el error.
  * **7.b: se reenvía una solicitud de compra ya confirmada.** El sistema reconoce la misma operación mediante su clave de idempotencia y evita cobrar o acreditar el inventario por segunda vez.

### Puntos pendientes
El precio concreto común del bambú por kilogramo, los precios y el catálogo final de insumos médicos, la precisión/validación de fracciones de kilogramo, las reglas de redondeo del coste y los valores máximos de cantidad no están fijados por la documentación actual. La especificación utilizará los valores configurados cuando existan y no establecerá cifras, precisión, redondeos ni límites nuevos.
