### Caso de Uso 5 (CU-05)
* **Nombre:** Editar Ficha Espécimen
* **Descripción:** el gestor del Zoo modifica uno o varios datos editables de la ficha técnica de un espécimen existente.
* **Actores:** Gestor del Zoo
* **Precondición:** existe el espécimen cuya ficha técnica se desea editar.
* **Postcondición:** se consolidan únicamente los cambios válidos solicitados en los datos editables de la ficha. La especie, nivel, alimentación, salud, satisfacción y estado vital no se modifican mediante este caso de uso. Las relaciones sociales conservan su integridad.
* **Situaciones de Error:**
  * La edición no se completa porque falla una validación o se produce un error durante la operación.
* **Situación del Sistema en caso de Error:**
  * Si ocurre un error antes de confirmar la operación, el sistema conserva íntegramente la ficha y las relaciones previas, sin aplicar cambios parciales ni recalcular métricas por la edición rechazada, y notifica el motivo.
  * Los cambios consolidados se registran como una modificación relevante del estado.
* **Flujo Básico:**
  1. El gestor del Zoo selecciona un espécimen existente y accede a su ficha técnica.
  2. Selecciona uno o varios datos editables: nombre, exactamente dos habilidades sociales, exactamente dos rasgos de personalidad, pareja y/o mejor amigo.
  3. Introduce los nuevos valores. Puede conservar sin cambios los demás datos editables.
  4. El sistema valida que el nombre no esté vacío, que haya exactamente dos habilidades sociales y dos rasgos de personalidad, y que los vínculos sociales cumplan sus reglas de validez.
  5. Al confirmar, el sistema vuelve a validar los datos y las entidades referenciadas.
  6. Si todas las validaciones son correctas, el sistema consolida la edición y las referencias recíprocas que correspondan como una única operación; no modifica los datos no editables.
  7. Tras consolidar una edición efectiva, el sistema actualiza las métricas afectadas y registra el cambio. La consulta o navegación de la ficha no provoca recálculos.
* **Flujo alternativo:**
  * **1.a: el espécimen ya no existe o no se puede acceder a su ficha al confirmar.** El sistema cancela la edición y conserva los datos existentes.
  * **2.a: se intenta modificar un dato no editable.** No se puede ya que no se da la opción de modificarlo.
  * **3.a: falta el nombre o no se indican exactamente dos habilidades sociales o dos rasgos de personalidad.** El sistema no confirma la edición; se recupera el estado anterior de la ficha técnica por lo que no se aplica ningún cambio.
  * **3.b: el nuevo nombre coincide con el de otro individuo.** El sistema lo acepta: los nombres no son únicos (RF-32).
  * **3.c: la pareja propuesta incumple una regla de validez.** El sistema rechaza la edición si la pareja no es de la misma especie y del mismo espacio, si alguno de los individuos no tiene al menos el nivel mínimo de pareja, si el vínculo no puede mantenerse recíproco o si alguno ya tiene otra pareja. El gestor corrige o elimina el vínculo.
  * **3.d: el mejor amigo propuesto no es otro espécimen del mismo espacio o se selecciona al propio espécimen.** El sistema rechaza el vínculo; el gestor selecciona otro espécimen válido o lo elimina. El mejor amigo puede pertenecer a otra especie.
  * **5.a: un valor o una entidad referenciada deja de ser válido antes de confirmar.** El sistema rechaza la operación completa y conserva la ficha y relaciones anteriores.
  * **5.b: falla una validación o se produce un error durante la persistencia.** El sistema no aplica cambios parciales; conserva la ficha anterior y notifica el error.
  * **6.a: no se modifica ningún dato.** El sistema no registra una mutación ni ejecuta recálculos.
