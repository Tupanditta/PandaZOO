### Caso de Uso 17 (CU-17)
* **Nombre:** Consultar Monitor de Satisfacción
* **Descripción:** el gestor consulta la satisfacción global del zoológico y su desglose por hábitat, espacio y espécimen individual.
* **Actores:** Gestor del Zoo
* **Precondición:** existe una partida seleccionada y se pueden consultar las métricas de satisfacción persistidas.
* **Postcondición:** el sistema presenta las métricas disponibles por nivel jerárquico sin modificar el parque ni recalcular la satisfacción durante la consulta.
* **Situaciones de Error:** las métricas no existen para un nivel, no se pueden recuperar o están incompletas.
* **Situación del Sistema en caso de Error:** el sistema identifica los datos no disponibles sin sustituirlos por ceros ni calcular métricas al abrir la vista. La consulta no modifica métricas, estado de animales ni datos de simulación.
* **Flujo Básico:**
  1. El gestor abre el monitor de satisfacción.
  2. El sistema consulta la métrica global de la partida y las métricas persistidas por hábitat, espacio y espécimen.
  3. El sistema muestra la satisfacción global y permite desplegar el desglose jerárquico desde el parque hasta cada individuo, utilizando nombres descriptivos y sin exponer identificadores internos.
  4. El sistema incluye en las métricas activas únicamente animales vivos con espacio asignado. Los datos de animales muertos o vendidos no se presentan como satisfacción activa.
  5. El sistema presenta las métricas con los valores y el formato de visualización definidos para cada nivel. Los niveles sin animales vivos se muestran sin métrica y no se incorporan a las medias de niveles superiores.
  6. El gestor consulta o navega entre niveles; la lectura de la vista no dispara cálculos, sondeos ni mutaciones.
* **Flujo alternativo:**
  * **1.a: no existe una partida seleccionada.** El sistema informa de que no hay métricas de partida que consultar.
  * **2.a: la satisfacción global no está disponible porque no existe una métrica persistida.** El sistema comunica que el valor no está disponible y no lo representa como cero.
  * **2.b: falla la recuperación de métricas de un nivel o entidad.** El sistema informa del dato afectado y mantiene disponibles las demás métricas recuperadas correctamente.
  * **3.a: hay entidades con nombres descriptivos repetidos o datos con claves internas.** El sistema usa el contexto jerárquico disponible para presentar las entidades sin revelar claves técnicas.
  * **4.a: un animal no está vivo o no tiene espacio asignado.** El sistema lo excluye de las métricas activas, conforme a las reglas de cálculo.
  * **5.a: un espacio, hábitat o partida no tiene animales vivos computables.** El nivel queda sin métrica y no aporta un valor a la media superior.
  * **6.a: el gestor vuelve a abrir o actualiza el monitor.** El sistema vuelve a leer las métricas persistidas sin recalcular satisfacción ni ejecutar el ciclo de simulación.

### Reglas y valores aplicables
Los valores numéricos proceden de las fórmulas de `EspecificacionBBDD.md` (sección 4) con los valores de `valores_y_pesos.json`. La satisfacción individual se muestra como porcentaje entero con los medios hacia arriba; un espacio u hábitat sin animales vivos no muestra métrica.
